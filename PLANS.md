# Execution plans

For work spanning multiple stages, create `docs/plans/YYYY-MM-DD-topic.md` with:
1. Goal and definition of done.
2. Inputs and version constraints.
3. Ordered steps with pending/in-progress/done states.
4. Evidence and validation commands.
5. Decisions, alternatives and deviations from the protocol.
6. Blockers and next executable action.

Keep the plan useful to a fresh Codex session. Do not put credentials or raw confidential code in plans. Update it as decisions change. An unexecuted plan is not a result.
