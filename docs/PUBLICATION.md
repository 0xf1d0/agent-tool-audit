# Publication and reproducibility

The ZIP contains original workflow code and synthetic fixtures. It excludes uploaded PDFs, private datasets, credentials, raw traces and a `.git` directory. Internal source notes are used to guide methodology; the original documents are not redistributed.

Before public GitHub publication, inspect staged files, agree licensing with the institution, and review real vulnerability disclosures with the relevant maintainers. A candidate is not a confirmed product vulnerability. Preserve exact affected versions and remediation context in any later public report.

Publish reviewed aggregate evidence and necessary redacted reproductions. Keep private raw artifacts in controlled storage with hashes referenced in reports. Do not include actual keys, machine paths revealing private data, captured prompts containing confidential code, or unpublished supervisor PDFs. Do not upload the Luxembourg dataset without verifying redistribution rights.

CI runs only the synthetic test suite and demo; it never executes real attacks, downloads datasets or calls paid models. GitHub publishing is left to the user.
